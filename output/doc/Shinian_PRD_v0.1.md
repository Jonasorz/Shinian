# Shinian 产品需求文档（PRD）

> 项目代号：Shinian  
> 文档版本：v0.1  
> 文档状态：MVP 草案  
> 更新日期：2026-07-23  
> 产品形态：自托管、单人使用的卡片笔记与轻量任务管理应用

## 1. 文档目的

本文档用于明确 Shinian 第一阶段的产品目标、范围、核心流程、功能需求、数据设计、技术约束和验收标准，为后续交互设计、技术方案和开发排期提供统一依据。

## 2. 产品背景

用户目前使用 flomo 记录碎片想法，使用滴答清单管理待办，但不希望继续为基础记录、任务管理和第三方同步能力支付订阅费用。用户拥有自己的 VPS，并在本地长期使用 Obsidian。

现有工具存在以下问题：

- 笔记与任务分散在两个应用中，想法与行动缺乏直接关系。
- 数据同步、API 和高级回顾等能力依赖付费订阅。
- Notion 使用频率较低，不适合作为核心数据平台。
- 数据由外部 SaaS 托管，长期成本、迁移和可控性不理想。
- 用户已经拥有 VPS，希望获得可长期维护、可迁移和可备份的个人系统。

## 3. 产品定义

Shinian 是一个部署在个人 VPS 上的卡片笔记与轻量任务管理系统。

产品以统一快速输入为入口，将内容沉淀为 Memo 或 Task，并支持两者相互关联。VPS 上的私有网页是主要操作界面，PostgreSQL 是主数据源，Obsidian 是可选的本地 Markdown 镜像和长期归档工具。

### 3.1 核心价值

1. 快速记录：像发送聊天消息一样记录想法或任务。
2. 想法到行动：Memo 可以转为 Task，Task 完成后可以沉淀为 Memo。
3. 主动回顾：通过每日回顾让旧笔记重新出现。
4. 数据自主：应用、数据库、附件和备份均由用户控制。
5. 长期可迁移：支持 Markdown 和 JSON 导出，不依赖特定平台。

### 3.2 产品原则

- 记录优先：减少标题、格式和分类带来的输入负担。
- 单人优先：第一阶段不为团队协作增加复杂度。
- 本地数据友好：数据必须能够完整导出并进入 Obsidian。
- 核心能力自建：不依赖 flomo、滴答清单或 Notion 才能正常运行。
- 渐进增强：优先交付 PWA，未来可增加 Android 和 iOS 客户端。
- 克制设计：不发展为复杂的项目管理或文档协作平台。

## 4. 目标用户

MVP 仅服务一个主要用户：

- 拥有个人 VPS。
- 经常记录碎片想法、灵感、读书摘录和工作复盘。
- 需要管理日常待办、截止时间和重复任务。
- 使用 Obsidian 保存长期知识资料。
- 重视数据所有权、隐私、备份和可迁移性。

MVP 不考虑多租户、团队空间、成员权限和商业化运营。

## 5. 产品目标与非目标

### 5.1 MVP 目标

- 在手机和电脑上快速创建 Memo 与 Task。
- 使用同一套标签体系管理笔记和任务。
- 建立 Memo 与 Task 之间的来源和关联关系。
- 提供今日任务、最近七天、收件箱和完成记录。
- 提供全文搜索、标签筛选和每日回顾。
- 支持图片附件、提醒和基础重复任务。
- 支持安装到手机或电脑桌面的 PWA。
- 支持完整 JSON、Markdown 导出和自动备份。
- 支持向本地 Obsidian 单向生成 Markdown 镜像。
- 能够从 flomo 和滴答清单导入历史数据。

### 5.2 明确不做

MVP 及可预见版本不包含：

- 习惯打卡。
- 四象限。
- 时间线或甘特图。
- 团队协作。
- 日历订阅。
- 复杂项目管理。
- 社区或公开内容广场。
- 复杂文档排版。
- 内置 Markdown 编辑器。
- Notion 同步。

以下能力不进入 MVP，但可以在后续独立评估：

- 番茄专注。
- AI 自动摘要、语义搜索和任务拆解。
- 原生 Android、iOS 客户端。
- 选择性公开发布页面。

## 6. 产品形态与系统边界

### 6.1 产品组成

1. 私有 PWA：主要记录、查询、回顾和任务管理入口。
2. VPS 后端：提供认证、业务逻辑、API、提醒和后台任务。
3. PostgreSQL：保存 Memo、Task、标签、关系和同步状态。
4. 附件存储：保存图片及后续可能支持的文件。
5. Markdown 导出器：将数据转换为 Obsidian 可读文件。
6. 备份服务：备份数据库、附件和配置。

### 6.2 数据主从关系

- VPS 数据库是唯一主数据源。
- PWA、未来 Android 和 iOS 客户端通过统一 API 访问数据。
- Obsidian 是单向 Markdown 镜像，不作为 MVP 的实时编辑源。
- flomo 和滴答清单只作为一次性迁移来源。
- Notion 不属于核心架构。

## 7. 信息架构

### 7.1 一级导航

移动端底部导航建议包含：

1. 首页
2. 笔记
3. 任务
4. 回顾
5. 搜索

设置、标签管理、数据迁移和备份入口放入个人菜单。

桌面端采用左侧导航，保留相同的信息结构。

### 7.2 核心页面

| 页面 | 主要内容 |
|---|---|
| 首页 | 统一快速输入、今日任务、最近 Memo、同步状态 |
| 笔记 | Memo 时间线、标签筛选、创建与编辑 |
| 任务 | 收件箱、今日、最近七天、清单、已完成 |
| 回顾 | 每日随机 Memo、去年今日、继续回顾 |
| 搜索 | 跨 Memo 和 Task 的统一搜索与筛选 |
| 标签 | 标签树、重命名、合并、使用统计 |
| 设置 | 账号、安全、提醒、Obsidian、导入导出、备份 |

## 8. 核心业务对象

### 8.1 Memo

Memo 是无标题要求的卡片式记录。

核心字段：

- 唯一 ID。
- 正文。
- 自动摘要或首行标题。
- 创建时间。
- 修改时间。
- 来源。
- 标签。
- 附件。
- 是否置顶。
- 是否归档。
- 删除时间。
- 内容版本号。

### 8.2 Task

Task 是可完成的行动项。

核心字段：

- 唯一 ID。
- 标题。
- 备注。
- 状态：Inbox、Todo、Doing、Done、Cancelled。
- 所属清单。
- 标签。
- 优先级：无、低、中、高。
- 开始时间。
- 截止时间。
- 提醒时间。
- 重复规则。
- 完成时间。
- 父任务 ID。
- 排序值。
- 来源 Memo ID。
- 创建时间与修改时间。
- 内容版本号。

### 8.3 Tag

- 唯一 ID。
- 完整路径，例如 `产品/个人系统`。
- 显示名称。
- 父标签 ID。
- 颜色或图标，可选。
- 创建时间与修改时间。

Memo 与 Task 共用同一套标签。

### 8.4 Relation

用于表达内容之间的关系：

- Memo 引用 Memo。
- Memo 生成 Task。
- Task 完成后生成 Memo。
- Task 关联参考 Memo。
- Memo 与 Task 的普通双向关联。

## 9. 功能需求

## 9.1 统一快速输入

### 需求说明

用户可以在首页输入框快速创建 Memo 或 Task。

### 交互要求

- 默认创建 Memo，避免输入前必须选择类型。
- 用户可以显式切换为 Task。
- 输入内容出现明确时间表达时，系统可以提示“创建为任务”。
- 支持粘贴文字、链接和图片。
- 支持快捷键唤起输入框。
- 移动端支持从系统分享菜单接收文字、链接和图片，作为后续增强。

### 验收标准

- 首页首屏可以直接输入，无须进入二级页面。
- 纯文字 Memo 在一次提交动作内完成创建。
- 创建成功后立即出现在时间线中。
- 网络中断时内容不会因页面关闭而直接丢失，至少保存本地草稿。

## 9.2 Memo 管理

### 功能范围

- 创建、查看、编辑、软删除和恢复。
- 时间倒序排列。
- 支持图片附件。
- 支持置顶。
- 自动识别正文中的 `#标签` 和 `#父级/子级`。
- 显示创建时间、修改时间和来源。
- 从 Memo 创建关联 Task。
- 复制 Memo 链接。

### 验收标准

- 编辑不会改变原始创建时间。
- 删除内容先进入回收站，不立即物理删除。
- Memo 中的标签与标签页统计保持一致。
- 从 Memo 创建 Task 后，可以从双方详情页跳转。

## 9.3 Task 管理

### 功能范围

- 创建、编辑、完成、取消、软删除和恢复。
- 收件箱。
- 自定义清单。
- 今日视图。
- 最近七天视图。
- 已完成记录。
- 优先级。
- 开始时间与截止时间。
- 一个或多个提醒。
- 基础重复任务。
- 子任务或检查项。
- 标签。
- 任务备注与图片附件。
- 与 Memo 建立关联。

### 重复规则

MVP 支持：

- 每天。
- 每个工作日。
- 每周指定星期。
- 每月指定日期。
- 每年指定日期。
- 按固定间隔重复。

重复任务完成时生成下一次实例，保留历史完成记录。

### 验收标准

- 完成任务后从未完成列表移除，并可在完成记录中查询。
- 今日视图包括今天开始、今天到期和已经逾期的未完成任务。
- 最近七天按日期显示未来七天内的任务。
- 重复任务完成后，下一次任务日期计算正确。
- 子任务完成状态不会意外覆盖父任务状态。

## 9.4 Memo 与 Task 联动

### Memo 转 Task

- 用户可从 Memo 操作菜单选择“创建任务”。
- 默认使用 Memo 首行作为任务标题。
- 原 Memo 保持不变。
- 新 Task 保存来源 Memo ID。

### Task 沉淀 Memo

- 用户完成任务时可选择“记录完成心得”。
- 系统创建一条新 Memo，并关联原 Task。
- 新 Memo 可继承任务标签。

### 统一检索

- 搜索结果同时展示 Memo 与 Task。
- 结果明确标识内容类型、状态和时间。

## 9.5 标签与清单

### 标签

- Memo 和 Task 共用标签。
- 支持多级标签。
- 支持标签重命名。
- 支持合并标签。
- 支持查看无标签内容。
- 删除标签不默认删除其下内容。

### 清单

- 清单仅用于 Task。
- 系统默认提供“收件箱”。
- 用户可以新增、重命名、排序和归档清单。
- 删除非空清单前必须选择迁移目标。

## 9.6 搜索与筛选

### 搜索范围

- Memo 正文。
- Task 标题和备注。
- 标签。
- 清单名称。

### 筛选条件

- 内容类型。
- 标签。
- 清单。
- 创建时间。
- 截止时间。
- 完成状态。
- 优先级。
- 是否包含图片或链接。

### 验收标准

- 搜索支持中文关键词。
- 多个筛选条件可以组合。
- 搜索结果返回后可以继续编辑或完成任务。
- 常用数据规模下，普通搜索应在 1 秒内返回首屏结果。

## 9.7 每日回顾

### 功能范围

- 每天生成一组旧 Memo。
- 用户可以配置回顾数量。
- 用户可以指定包含或排除的标签。
- 用户可以配置时间范围。
- 支持“换一组”。
- 支持“去年今日”。
- 回顾页可以直接编辑、添加标签或创建 Task。

### 默认规则

- 每日 8 条。
- 默认从 30 天以前的 Memo 中抽取。
- 排除已删除和已归档内容。
- 尽量避免短期内重复展示同一条 Memo。

## 9.8 提醒与通知

### 通知渠道

MVP 首选：

- 浏览器及 PWA Web Push。
- 应用内提醒中心。

可选备用：

- 邮件。
- ntfy 或其他自托管推送渠道。

### 验收标准

- 用户可以授权或关闭通知。
- 提醒任务在设定时间进入通知队列。
- 通知失败会记录状态并重试。
- 时区统一使用用户设置，默认 Asia/Shanghai。

## 9.9 PWA

### 功能范围

- 可添加到手机和电脑桌面。
- 使用独立图标和启动画面。
- 在独立窗口运行。
- 缓存应用外壳和必要静态资源。
- 支持本地草稿。
- 网络恢复后可以重新提交失败操作。

MVP 不承诺完全离线浏览全部历史数据，但必须保证新输入不会轻易丢失。

## 9.10 Obsidian 单向同步

### 同步方向

`VPS 数据库 -> Markdown 文件 -> 本地 Obsidian`

### Memo 文件格式

每条 Memo 生成独立 Markdown 文件，Frontmatter 至少包含：

```yaml
---
id: memo_01J8ABC
created: 2026-07-23T10:30:00+08:00
updated: 2026-07-23T10:35:00+08:00
tags:
  - 产品/个人系统
source: web
---
```

正文位于 Frontmatter 之后。

### Task 文件格式

任务可以按日或按清单聚合，使用 Obsidian Tasks 兼容的 Checkbox 表达：

```markdown
- [ ] 完成 VPS 部署 📅 2026-07-30
  - ID: task_01J8XYZ
  - 来源：[[自托管个人系统]]
  - 标签：#项目/个人系统
```

### 传输方式

MVP 优先提供：

1. 手动生成并下载 Markdown 压缩包。
2. 在 VPS 生成稳定的 Markdown 目录。

后续可以增加 Git、Syncthing 或 WebDAV 自动传输。Obsidian 始终作为单向 Markdown 镜像，不支持从 Obsidian 修改后回写 VPS。

## 9.11 导入、导出与迁移

### 导入

- flomo HTML 或可获得的官方导出文件。
- 滴答清单 CSV 或可获得的官方备份文件。
- 通用 Markdown。
- 通用 JSON。

所有导入任务必须：

- 先预览数量和字段映射。
- 能识别重复记录。
- 记录导入批次。
- 支持撤销整个导入批次。

### 导出

- 全量 JSON。
- 全量 Markdown。
- 按标签、清单、日期和类型筛选导出。
- 附件随导出包保存。

## 9.12 备份与恢复

### 备份范围

- PostgreSQL 数据。
- 图片及附件。
- 应用配置。
- 加密后的必要密钥备份，可选。

### 默认策略

- 每日自动备份。
- 至少保留最近 30 个每日版本。
- 支持下载备份。
- 支持手动创建备份。
- 定期执行恢复演练。

### 验收标准

- 备份失败会在设置页显著提示。
- 文档中提供完整恢复步骤。
- 可以在干净环境中从备份恢复核心数据。

## 9.13 认证与安全

MVP 为单用户系统，但仍需完整认证：

- 用户名或邮箱加密码。
- 密码使用可靠的单向哈希算法。
- 支持安全会话和退出全部设备。
- 登录失败限速。
- 全站 HTTPS。
- CSRF、XSS 和文件上传校验。
- 敏感密钥仅保存在服务端环境变量或密钥文件中。
- 删除账号或清空数据属于高风险操作，必须二次确认。

若系统不需要公网访问，可选用 Tailscale 等私有网络进一步缩小暴露面。

## 10. 非功能需求

### 10.1 性能

- 常用页面首屏在正常网络下应快速可用。
- 10,000 条 Memo 与 10,000 条 Task 规模下，分页、筛选和搜索仍可正常使用。
- 图片使用缩略图和懒加载。
- 后台同步、导入和备份不得阻塞前台记录。

### 10.2 可靠性

- 所有创建和修改接口必须具备幂等或防重复策略。
- 后台任务支持失败重试。
- 数据库迁移可追踪并可回滚。
- 删除默认采用软删除。

### 10.3 可维护性

- 使用 Docker Compose 部署。
- 配置与代码分离。
- 提供健康检查、结构化日志和基础监控。
- 提供版本升级及数据库迁移说明。

### 10.4 可扩展性

后端 API 不绑定 PWA，为未来客户端保留：

- Android。
- iOS。
- 浏览器扩展。
- MCP 服务。
- 命令行工具。

每个业务对象必须使用全局唯一 ID、修改时间、版本号和删除标记，为离线同步及多客户端冲突处理打基础。

## 11. 建议技术架构

### 11.1 推荐组件

- 前端：TypeScript Web 框架，支持响应式设计与 PWA。
- 后端：Node.js + TypeScript。
- 数据库：PostgreSQL。
- 搜索：MVP 使用 PostgreSQL 全文及模糊搜索能力。
- 附件：VPS 本地目录，抽象为可替换的对象存储接口。
- 后台任务：数据库队列或轻量任务队列。
- 反向代理与 HTTPS：Caddy 或现有网关。
- 部署：Docker Compose。

### 11.2 API 设计原则

- 所有客户端使用同一套版本化 API。
- 创建操作支持客户端生成请求 ID，防止重复提交。
- 返回对象包含 `id`、`createdAt`、`updatedAt`、`version`。
- 更新时检查版本号，避免静默覆盖。
- 删除使用软删除并提供恢复窗口。

## 12. 关键用户流程

### 12.1 快速记录 Memo

1. 用户打开 PWA。
2. 首页输入框获得焦点。
3. 用户输入想法并提交。
4. 系统保存 Memo、解析标签并更新列表。
5. 后台异步处理附件、搜索索引和 Markdown 导出状态。

### 12.2 从 Memo 创建 Task

1. 用户打开 Memo 操作菜单。
2. 选择“创建任务”。
3. 系统预填任务标题和标签。
4. 用户设置截止时间、清单和提醒。
5. 系统保存 Task，并建立双向关系。

### 12.3 完成 Task 并记录复盘

1. 用户完成 Task。
2. 系统询问是否记录完成心得。
3. 用户输入简短复盘。
4. 系统创建 Memo，继承标签并关联 Task。

### 12.4 每日回顾

1. 用户进入回顾页或点击回顾通知。
2. 系统展示当天的旧 Memo。
3. 用户浏览、编辑、补充标签或创建 Task。
4. 系统记录已展示时间，减少近期重复。

### 12.5 导出到 Obsidian

1. 用户在设置中触发 Markdown 导出。
2. 系统生成稳定目录结构与附件引用。
3. 用户下载压缩包或由同步工具传输目录。
4. Obsidian 打开目录并正常识别 Frontmatter、标签和链接。

## 13. MVP 验收清单

以下条件全部满足后，MVP 才视为可用：

- 能在 VPS 上通过 Docker Compose 完成部署。
- 能在手机和桌面浏览器登录。
- PWA 可以添加到桌面并独立运行。
- 可以创建、编辑、删除和恢复 Memo。
- 可以创建、编辑、完成、删除和恢复 Task。
- 收件箱、今日、最近七天和已完成视图结果正确。
- 支持截止时间、提醒、优先级、清单、标签和基础重复任务。
- Memo 与 Task 可以相互关联并跳转。
- 搜索可以同时查询 Memo 与 Task。
- 每日回顾能够按配置生成内容。
- 图片可以上传、查看并随备份保存。
- 可以导入一份 flomo 历史数据样本。
- 可以导入一份滴答清单历史数据样本。
- 可以导出完整 JSON 和 Markdown。
- Markdown 可以被 Obsidian 正常打开。
- 每日备份可执行，并完成至少一次恢复验证。
- 核心功能在 10,000 条模拟数据下可接受。

## 15. 成功指标

这是个人系统，指标用于判断产品是否真正替代现有工具，而非衡量商业增长。

- 连续 30 天无需打开 flomo 即可完成日常记录。
- 连续 30 天无需打开滴答清单即可完成任务管理。
- 90% 以上的新 Memo 能在 10 秒内完成记录。
- 任务提醒无明显漏发。
- 每周至少产生一次旧 Memo 的有效回顾或二次行动。
- 任意时刻可以在不依赖应用服务的情况下恢复完整数据。
- Obsidian 中可以查阅完整的 Memo 历史和任务归档。

## 16. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| PWA 在 iOS 后台能力有限 | 通知和后台同步可能不如原生 App | 使用 Web Push、应用内状态补偿；未来增加原生客户端 |
| Obsidian 被误作主数据源 | 可能造成版本分叉或数据覆盖 | 明确以 VPS 数据库为唯一主数据源，Obsidian 永久保持单向输出 |
| 自建服务运维失败 | 数据丢失或无法访问 | 自动备份、异地副本、恢复演练和健康检查 |
| 重复任务规则复杂 | 容易出现错误日期 | MVP 限定规则集合并建立完整测试 |
| 历史数据格式不稳定 | 导入失败或字段缺失 | 基于真实导出样本开发，先预览再导入 |
| 功能范围膨胀 | 延迟交付并增加维护成本 | 严格遵守非目标清单，新增需求进入后续评审 |

## 17. 待确认事项

1. 应用正式名称与视觉风格。

3. 是否只通过私有网络访问，还是需要公网域名。
4. 图片附件的预计规模和异地备份位置。

7. Obsidian 自动传输优先选择 Git、Syncthing 还是 WebDAV。
8. MVP 是否必须包含自然语言时间识别。
9. 提醒是否仅使用 Web Push，还是同时启用邮件或 ntfy。
